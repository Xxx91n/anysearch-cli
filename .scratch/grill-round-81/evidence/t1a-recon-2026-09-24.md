## 2. fake-ip 审计（环境常量）

- 本机解析（TUN/fake-ip）：`api.anysearch.com → 198.18.0.34`（与任务书先验一致，复核确认）；`status.anysearch.com → 198.18.1.48`；`anysearch.com → 198.18.0.158`。
- 代理解析路径：fake-ip 段 RFC2544 198.18.0.0/15；TUN 接管后由 Clash 按域名转发——**fake-ip 不构成通信障碍的实测证**：curl 直连 fake-ip:443 拿到了携带 X-Amz-Cf-* 头的真 CF 应答（请求真实抵达 CloudFront NRT20-P9）。
- DoH 对照（cloudflare-dns.com + dns.google 双源一致）：真 A=3.173.238.0/24 段四个 IP。fake-ip vs 真 DNS 双路径同结论（见 T2 矩阵格）。
- **环境常量锁定**：本轮全程 fake-ip=198.18.0.34 不切换（T2 纪律）。

## 3. 关键新事实：ANYSEARCH_ENDPOINT 本机常驻重定向

- `env` 实测：`ANYSEARCH_ENDPOINT=http://127.0.0.1:20128/v1/search` + `ANS_LLM_BASE_URL=http://127.0.0.1:20128/v1`；**Windows User 级注册表常驻**（`[Environment]::GetEnvironmentVariable('ANYSEARCH_ENDPOINT','User')` 返回值同上）——本机用户会话下所有进程默认把 anysearch provider 钉到 127.0.0.1:20128。
- 20128 端口现状：**活着但非 anysearch 服务**——`/health` 与 `/` 返回 OmniRoute（AI Gateway for Multi-Provider LLMs）的 Next.js Web UI HTML；`/v1/search?query=test` 返 HTTP 200 但为 catch-all HTML（非 anysearch JSON 协议）。
- install-smoke 设计佐证（scripts/install-smoke.mjs:193）：`ANYSEARCH_ENDPOINT=http://127.0.0.1:9` dead-port fault-injection——该 env 的语义即「本地端点重定向」，R62 立法在案。
- **对 R71 000 的释义冲击**：R71 spike 若在本机用户会话跑 live search，provider 实际打 127.0.0.1:20128；该端口当时无监听 → TCP connection refused → fetch 抛错 → **HTTP 000 形态完全吻合**（000=连接级失败，与「远端 404」不同类）。000 从未证明 api.anysearch.com 死——它可能从未被真正请求过。

- ci.yml `test-online` job 仅含：`packages/store test:online`（vector-arm golden）+ `packages/embedding test:online`（模型下载）——**无 api.anysearch.com provider 探针**。
