背景：一个 CLI 仓库以「governance grill round」推进治理，已完成 78 轮（每轮一个主题，裁决记入 ADR，债项记入 deferred-registry）。刚落地的第 78 轮是「门禁工具链校准轮」：(a) 重构了仓库自研的 machine-local path lint 判定器（检测提交文档中裸写的本机绝对路径），(b) 对包管理器「发布龄期闸」（minimumReleaseAge，拦截发布未满 48h 的版本被安装）做了 7 格预登记判决矩阵实测。随后独立审计窗产出残账：

残账1（F-3 教义缺口）：pathlint 实现里「仓库内目标的绝对路径必须改写为相对路径、marker 不豁免」这条规则，在被 marker 覆盖的代码围栏内和 Stack: 定位行里实际不生效——实现与 ADR 文本存在既往张力（旧码搬移遗留，非本轮引入）。裁决方向是二选一：收紧实现，或修订 ADR 文本显式承认豁免域。
残账2（F-4 噪音政策）：判定器在 fence 内对「单段未知根 POSIX 路径（如 /x）」仍产出 info 级 surfaced 噪音（非阻断），先于 fenced 分支判定产出——裁决「静默」还是「保留可见」。
残账3（WORD_CHAR 误报）：判定器词字符集缺下划线，foo_C:\x 这类标识符粘连盘符形会误报——边缘 FP 处置裁决。
残账4（E6 证伪后果）：实测证明「发布龄期闸在 lockfile 回放路径不执法」——一旦未成熟版本进入 lockfile，--frozen-lockfile 安装静默放行。若 CI 依赖 frozen install 拦截未成熟版本则实际无机器腿护栏。裁决：立机器腿护栏（lockfile 未成熟版检测）还是显式接受残余风险记档。
另有一项跨轮排程义务：上游依赖每周发版观测（L0 快照+L1 diff 例行取证），刚有新 alpha 版发布，取证义务到期但纯证据零代码。
其余 11 条 deferred 债均外部阻塞或半响，本轮无可做项。

研究问题：
1. 「审计发现残账清算」作为一轮工作的主题定界：把同一次审计产出的多个小型发现（教义张力裁决/噪音政策/误报边缘/护栏缺口）打包成一轮，在软件治理/安全审计跟进惯例里是成熟做法还是「杂物筐」反模式？业界对 audit finding remediation 的批处理粒度与主题内聚性有什么模型（如按子系统、按发现类型、按风险等级分批）？
2. 「实现与文档/政策张力」的裁决心智模型：当 lint/策略检查的实现行为与书面政策（ADR/规范文本）长期不一致时，业界惯例是「实现向文档收敛」还是「文档向实现收敛」？判据是什么（哪个是意图、哪个是 drift）？policy-as-code 与 compliance-as-code 领域对此有没有成熟框架？
3. 「安全/供应链控制被证伪后的护栏补漏」惯例：当实测发现某控制存在绕过路径（本例：龄期闸不覆盖 lockfile 回放），业界处置光谱是什么——补偿控制（compensating control）、纵深防御补腿、还是显式 risk acceptance 记档？每层选择的判据？
4. 小型治理发现捆绑的风险：把「需要立法裁决的教义分叉」（残账1）与「纯工程修正」（残账2/3）与「护栏设计」（残账4）混在一轮，是否会稀释裁决质量？有没有「一轮一主题」边界的成熟判据来判断这个捆绑是否内聚？

请给出 R79 主题定界的推荐方案与理由，重点在工业界成熟落地的心智模型与可引用先例。
