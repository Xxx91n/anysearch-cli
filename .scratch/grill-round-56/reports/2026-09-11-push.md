### 2.1 ci.yml failure analysis (failure)

**Conclusion**: Pre-existing CI breakage, NOT a regression from this PR.

Evidence from main @ 53ac27c (immediately before this PR):
- main @ 53ac27c ci run 34593204058 = **failure** (same MCP database error)
- Verified by: `gh run view 34593204058 --log | grep "Cannot open database"` returns the same error line

Failure mode: `anysearch MCP server error: Cannot open database because the directory does not exist`

The ci.yml smoke test runs `node apps/mcp/dist/index.cjs --transport stdio` against the MCP server's protocol handshake. The MCP server's transport startup calls `createEngine(undefined, { dbPath: resolveDbPath() })` which calls `resolveDbPath()` -> `~/.anysearch/anysearch.db`. The dir `~/.anysearch/` is not auto-created in this code path (only apps/cli/src/db.ts:createPersistentEngine calls mkdirSync).

**This bug pre-dates ADR-0056** and is unrelated to my PR's surface (session/trace ID propagation). The user mandate was to implement ADR-0056, not fix pre-existing CI environment bugs.

Recommended follow-up (out of ADR-0056 scope): add `mkdirSync(dirname(dbPath), { recursive: true })` at `apps/mcp/src/index.ts:createEngine` call site, or extract a `createPersistentEngine` helper to apps/mcp/src/db.ts mirroring apps/cli/src/db.ts.
