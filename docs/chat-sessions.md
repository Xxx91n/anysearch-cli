# 新建对话和续聊

`ans chat "问题"` 每次新建对话，并显示 `[session] ID`。

- `ans chat --continue "问题"`：续当前项目最近一段对话。
- `ans chat --session ID "问题"`：续指定对话，换目录也能用。
- `ans chat --list`：查看当前项目的会话。

## 在脚本里提问

- `ans chat -p "问题"`：标准输出只有答案和来源，会话句柄和运行信息写到标准错误。会话被占用或没有拿到答案时，命令退出非零。
- `ans chat -c`：接着问当前项目最近一段会话里被打断的问题，输出格式和 `-p` 一样。要指定会话，用 `ans chat -c --session ID`。找不到被打断的问题时，命令会说明原因并退出。

## 同一段会话被两处同时使用

一次对话是一次「尝试」：先占住这段会话，记下「开始了」，跑完，记下结果，再交还。占的和放的是同一段范围，所以两个进程同时收尾也不会互相盖住——后发起的那个根本记不下「我也开始了」，它会在占住那一步直接失败。

撞车时先明确告知「这段会话正在别处运行」和句柄。没有终端就立即失败；有终端时按下文选择 fork、等待或不动。默认不排队等。

最近会话的排序在同一毫秒里也准：登记序号严格递增，不靠句柄文字决定先后。

续聊之前会先把整份对话记录读一遍，给出一个判决。判断本身不写盘：

- 中间有一行读不出来，就拒绝并说出是第几行，不把短了一截的历史当成完整历史。
- 最后一行没有换行符，是写到一半被杀留下的碎片，不算事实，读的时候忽略。这份碎片在下一次追加之前被切掉，所以一次写盘失败不会把这段会话永久锁死。切割按原始字节算，不按解码后的文字算——一个汉字被切成一半时，按文字算会多算一两个字节，连带削掉上一行的换行符，下一轮就会把一整条真实消息当成碎片丢掉。
- 文件头的格式版本比本程序新，或者出现本程序不认识的事件种类，就拒绝打开，不猜内容。
- 身份三道要对上：文件头里的 id、文件名里的 id、请求的句柄。对不上就拒绝，不在原句柄下悄悄新建空对话，也不张冠李戴。

被拒绝的记录，原文件一个字节都不改。只有上面那种断尾会被切掉，而且切在拿到写锁之后。

`ans chat --list` 照样列出有问题的会话，每行后面写明是哪种问题；一条坏记录不会让整个列表失败。

## 会话被占用时

`ans chat` 发现同一会话正在别处运行时，stdin 不是终端就立即失败，退出码为 1，错误里带原句柄。有终端则问一次：输入 `1` / `fork` / `f` 另开一份，或 `2` / `wait` / `w` 等原来的运行结束。直接回车、输入其他内容或读不到答案都不动，返回非零；`ANS_NO_INTERACTIVE=1` 同样不提问。

fork 把选择时已经完整写入的记录复制到新句柄；未写完的尾行不带入，原记录不改。终端会打印 `[session] 已 fork，新句柄：…`，之后可用 `--session` 指定它。新会话保留原项目归属，本次任务预算继续归本次执行。

这是 #315/#317 对 #266「默认等待两分钟」决定的调整，不是修复那个决定的实现。底层运行锁现在默认不等待；只有调用方显式传正数 `waitMs`（或设置 `ANS_PI_LOCK_TIMEOUT_MS`）才等待。终端明确选择等待时，等待租约最多两分钟，可由该环境变量调整。MCP 没有终端交互，撞车仍立即报错。
