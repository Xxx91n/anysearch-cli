# 配置和数据放在哪：`.ans`

一句话说清：**用户级一个目录 `~/.ans`，项目级一个目录 `<项目>/.ans`，所有文件的位置只在 `packages/store/src/ans-paths.ts` 里定义一次**（两处例外写在文末「这次没做的」里：发布脚本不能 import TypeScript，嵌入包是零依赖叶子包）。 以前是两套名字并存（`~/.anysearch` 和 `~/.anysearch-cli`，项目里同样两个），同一个设置到底在哪个目录里，每个读代码的人都要自己猜一遍。现在不用猜了。

## 两个根

| 范围 | 目录 | 怎么算出来的 |
| --- | --- | --- |
| 用户级 | `~/.ans` | `USERPROFILE`（Windows）或 `HOME`，都没有就用系统给的家目录 |
| 项目级 | `<项目>/.ans` | 当前工作目录 |

环境变量名不变，还是 `ANS_*`。这次只改目录名。

## 每个文件住哪

用户级（`~/.ans/`）：

| 文件 | 是什么 |
| --- | --- |
| `anysearch.db` | 持久库：会话、消息、预算账、任务登记、观测 |
| `project-index.db` | 所有项目共用的项目索引，按 `project_path` 列分开 |
| `config.env` | `ans domain` 写下的当前领域（`ANS_DOMAIN`） |
| `config.toml` | 用户级 `[llm]` 配置 |
| `credentials.json` | 明文、仅本人可读的 provider 密钥 |
| `server-token` | 本机安装的那一个服务令牌 |
| `server.json` | 插件服务实际监听的地址 |
| `session` | 观测用的会话锚点 |
| `skills/` | 用户级装好的技能 |
| `MEMORY.md` | 用户级记忆投影（每次重新生成） |
| `models/` | 嵌入模型缓存 |
| `pi-sessions/` | 对话记录，跟着库走 |
| `attribution-gold-revisions/` | 归因校准的版本根 |
| `host-wiring/` | 宿主接入的操作日志和写前备份 |
| `.layout.json` | 这次改名搬了什么、什么没搬、为什么 |

项目级（`<项目>/.ans/`）：

| 文件 | 是什么 |
| --- | --- |
| `config.toml` | 项目级 `[llm]` 配置，也是「这个目录是个项目」的标记 |
| `skills/` | 项目级技能 |
| `policy.json` | 钩子侧的网址策略缓存 |
| `hitl.pending` | 无人值守时被拦下的网址队列 |
| `routing-card.json` | 用户自己写的路由卡覆盖 |
| `MEMORY.md` | 项目级记忆投影 |
| `pi-agent/` | PI 的项目内临时目录 |
| `host-wiring/` | 项目级接入日志和备份 |

## 旧目录怎么处理

**用户级：第一次运行自动搬一次。** CLI、MCP、插件服务启动时都会先跑 `ensureAnsLayout()`：

1. `~/.anysearch` 和 `~/.anysearch-cli` 里的东西逐个搬进 `~/.ans`。普通文件用改名，跨盘时改成「复制 → 删源」。
2. **数据库不搬，只复制。** 正在跑的插件服务可能开着库，把主文件从 `-wal` 底下挪走就是损坏数据库的经典做法。所以用 SQLite 自己的在线备份（`VACUUM INTO`，和 #310 用的是同一套）复制一份到新位置，**旧文件原地留着**，当作升级前的副本。
3. 新目录里已经有同名文件时，**保留新的那份**，旧的那份不动，记进 `.layout.json` 的 `pending`，并在标准错误上说清楚是哪一条。
4. 搬空的旧目录会被删掉；没搬空的留着。
5. 没搬成的条目**下次运行会再试**，并且每次都逐条报出来（不是只报第一次）。
6. **搬迁记录不是通行证。** 每次运行都会重新看一眼旧目录，所以搬完之后旧目录里又冒出来的东西（比如老版本 `ans` 又写了一回）下一次运行照样会被搬；一条记录只说明「上次搬的时候是什么情况」，不代表以后不用看。

**项目级：在项目里跑一次 `ans` 就搬。** 项目目录可能有很多个，所以不扫盘，只搬当前这一个：`ans` 在某个项目里跑的时候，把 `<项目>/.anysearch` 和 `<项目>/.anysearch-cli` 里的东西搬进 `<项目>/.ans`。项目目录里通常是纯改名，失败下次再试，不需要记录文件。

这里有个例外：**项目级的数据库不搬。** 产品的项目索引库住在用户根（`~/.ans/project-index.db`），按 `project_path` 列分项目，不是每个目录一个库，所以 `<项目>/.anysearch/project-index.db` 这类文件在新布局里没有对应位置，搬过去只会让一份旧数据看起来像活的。这类文件原地留着，`ans` 在那个项目里运行时会说明它是什么、可以删掉，或者用 `ANS_PROJECT_DB` 指过去。数据库也不许改名——从 `-wal` 底下搬走就是损坏。

**钩子只读兼容，不搬。** 钩子跑在宿主的工具调用热路径上，不适合写盘。所以钩子读的时候先看 `.ans`，没有再退回旧名字。你在那个项目里跑一次 `ans`，目录就搬过去了。

**只读命令不搬。** `ans upgrade status` 是「只读不改」，`ans doctor` 是用来看当前状态的——在它们前面搬目录，等于让报告描述一个它自己刚改过的布局。这两条走读时兼容，照样答得对。

**读的时候永远先看新名字。** 每个路径解析函数都是「新文件在就用新的，不在就用旧的，都没有就返回新路径」。所以升级不会从空配置或空库开始，也不会因为搬了一半就读不到东西。写的时候用的是同一个解析结果——一个设置只落在一个文件里，不拆成新旧两份。

**对话记录跟着布局根走，不跟着库走。** `pi-sessions/` 在 `~/.ans` 下；只有显式设了 `ANS_DB_PATH` 时才放到那个库旁边。这样「库没搬成、目录搬成了」的时候，历史会话照样读得到。

## 出问题的时候

- **`~/.ans` 建不出来**（没权限、盘满）：直接报错并停下，命令不执行。旧目录原样保留，什么都没丢。修好权限再跑。
- **数据库复制失败**：标准错误上说明原因，旧库继续原地用，本次照常工作。`.layout.json` 里记着这一条，下次再试。
- **某个文件搬不动**（被占用、权限不够）：标准错误上逐条列出路径和原因，本次继续从旧位置读，下次再试。

`.layout.json` 长这样：

```json
{
  "version": 1,
  "migratedAt": "2026-11-20T00:00:00.000Z",
  "moved": [{ "from": "…/.anysearch/config.env", "to": "…/.ans/config.env", "how": "moved" }],
  "pending": [{ "path": "…/.anysearch/anysearch.db", "reason": "…" }]
}
```

`how` 有三种：`moved`（改名）、`copied`（跨盘复制）、`snapshot`（数据库在线备份）。

## 升级后要做什么

1. 正常用就行。第一次运行会搬；搬干净了不吭声，有没搬成的才在标准错误上逐条列出来。
2. 确认新目录里的东西都在（`ans doctor`、`ans chat --list`、`ans skill list`）。
3. 满意之后，`~/.anysearch` 和 `~/.anysearch-cli` 里剩下的东西可以自己删。**程序不会自动删**——旧库是升级前的副本，删不删由你决定。项目里的旧目录同理，搬完就空了，可以直接删。

## 这次没做的

- **不扫盘找项目**：只搬当前工作目录那一个项目，别的项目等你下次进去跑 `ans`。
- **不删旧数据**。旧库、旧会话、旧账都留着。
- **不接管升级流程**。真正在「暂停新任务 → 等收尾 → 换文件」里做布局迁移的是 #311；这里只保证改名本身不丢东西。
- **不改环境变量名**。`ANS_*` 一个都没动。
- **两处位置不是从 `ans-paths.ts` 取的**：`scripts/ans-home.mjs`（发布脚本跑在 TypeScript 之外，照抄同样的两条规则）和 `@anysearch-cli/embedding` 的默认缓存目录（零依赖叶子包，默认值由 store 在加载前用 `setModelCacheDir` 覆盖）。

## 这是一次破坏性变更

写死了旧路径的外部脚本、shell 别名、CI 配置都会失效。要改的地方：把 `~/.anysearch` 和 `~/.anysearch-cli` 换成 `~/.ans`，把项目里的 `.anysearch` 和 `.anysearch-cli` 换成 `.ans`。环境变量不用改。
