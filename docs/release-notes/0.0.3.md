# v0.0.3 — first npm release

This is the first public npm release of the anysearch suite. We published it by
hand (`pnpm -r publish`), so npm has no provenance attestation for these
packages (D-006). That is how the manual release model works, not a defect:
provenance needs a cloud-hosted runner. After publishing, the registry side
(version, dist-tags, access, repository) was checked separately, following
docs/publishing.md.

## Packages

- `@anysearch-cli/cli@0.0.3` — the `ans` command (search / research / memory / knowledge)
- `@anysearch-cli/mcp@0.0.3` — MCP server (`ans_*` tools, stdio + HTTP)
- `@anysearch-cli/plugin@0.0.3` — plugin for agent hosts (hooks + adapters)
- `@anysearch-cli/embedding@0.0.3` — optional vector search add-on
  (**peer-optional**: not installed automatically; install it yourself with
  `npm i -g @anysearch-cli/embedding`)

The internal packages (`kernel`, `store`, `retriever`) are built into the
apps' `dist` and are not published; the apps ship as bundled packages (D-005).

## Highlights

- Only results from allowed websites are kept: both the allow list and the
  block list are checked, and when nothing is left the tool says so instead of
  making something up.
- Memory eval runs offline and gives the same result every time: 126 of 126
  cases pass, fingerprint `4a529f6fbe2096c8`
- Apache-2.0 license

## Fixed since the R62 audit

- Duplicate memories are now merged even when the embedding add-on is missing.
  If no cosine score can be computed, the code compares words instead
  (Jaccard fallback, θ=0.80). Decisions made this way are counted in
  `ConsolidateReport.embeddingAbsent` (D-002).

## Known limitations (short list — see README)

- Checking exact page URLs in live tests (`mustHitUrl`): 10 of the 12 live golden cases are
  quarantined because providers keep changing their URL shapes (TTL
  2026-10-14, the list can only shrink). Host-level evidence is 12 of 12;
  the active live checks are 1 host-level case and 1 case that checks the
  tool refuses to answer.
- macOS is only an observation lane and does not block releases (the
  `libc++abi` crash at exit). Probe data point #1 also showed a red
  registration step.
- On Windows the `libc++abi` crash at exit can overwrite the exit code for
  "no answer", so automation must read the structured `abstain` field instead.
