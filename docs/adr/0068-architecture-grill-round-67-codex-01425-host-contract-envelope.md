## Context

Round 66 closed Claude Code's contract family (envelope). Round 67 is the
same dual-theme shape on the second family: (B) prove the stack on **real
codex-cli 0.142.5** (Windows 11, `codex exec --json` headless) and (A)
publish `0.0.5` via the OIDC trusted-publishing channel established in R66.

The Codex grill surfaced a distinct defect set — the hosts share the
`hook_event_name` stdin field but NOT the stdout/config contract:

1. **Shipped `configs/codex/hooks.json` registered zero hooks.** The 0.0.4
   file used `{name, command, args}` per event entry — a shape Codex neither
   parses (unknown-field errors when strict) nor executes (silent no-op when
   lax). The official schema is
   `{ "<Event>": [{ matcher, hooks: [{ type:"command", command, timeout }] }] }`.
2. **Bare top-level `additionalContext` is ~80%-dropped.** SessionStart
   envelope legs delivered 4/4; plain-text 3/3; the bare form landed 1/8
   (synthetic stub) and 1/3 (published artifact) — a racy channel, not a
   clean reject. The published adapter + session-start emitted exactly the
   broken form.
3. **`decision.permission` was silently dropped** — the adapter only ever
   emitted `additionalContext`, so a URL-policy deny produced NO stdout and
   the tool call executed. Envelope `permissionDecision:"deny"` blocks
   (router log: `Tool call blocked by PreToolUse hook`); legacy
   `{decision:"block"}` also blocks; exit code 2 does NOT block.
4. **Hook matchers are FULL-MATCH regexes** — `mcp__anysearch__` does not
   match `mcp__anysearch__search_web`; `.*` and suffix-anchored patterns do.
5. **`-c` cannot express hooks** — the `-c` value parser treats
   `hooks.X=[{...}]` as a string (error: "expected a sequence"). Hook
   definitions must live in a config file layer (`config.toml` `[[hooks.*]]`
   or project `.codex/hooks.json`), not CLI injection.
6. **Env propagation to hooks confirmed** — `ANS_SERVER_*`/`ANYSEARCH_*`
   reach hook process env; the earlier "no index" legs were a config-layer
   bug (`--ignore-user-config` skips project `.codex/`), not env loss.
7. **required=true MCP hard-exits** — matches Codex docs; fail-open remains
   the responsibility of our tools/hooks themselves.
8. **Hook trust = persistent `[hooks.state]` sha256 entries** in
   `config.toml` (plugin-style keys `<src>:<file>:<event>:<i>:<j>`);
   headless probes use `--dangerously-bypass-hook-trust` and are labeled as
   such.

## Decision

### D1 Dual-theme serial round (ledger D-001; T1–T7)

Theme B (Codex host verification + fixes) must be fully green before Theme A
(release engineering) opens. Published `0.0.4` is the authoritative defect
object; `pnpm pack` tarballs are the candidate track; repo build output
never stands in for shipped behavior.

### D2 Fix set (ledger D-003; T3)

- `apps/plugin/configs/codex/hooks.json`: regenerated by
  `scripts/gen-claude-configs.mjs` from a `CODEX_HOOKS_SPEC` — official
  schema, commands are package bins (`ans-hook-codex` [new bin] +
  `ans-hook-session-start --envelope`), matchers suffix-anchored to the
  tool-name contract (`.*(search_web|research_web|recall_memory|
  query_knowledge|ans_chat)$`) — namespace-agnostic, full-match-safe.
- `apps/plugin/src/hooks/adapters/codex.ts`: PreToolUse emits a single
  `hookSpecificOutput` envelope carrying `additionalContext` +
  `permissionDecision`/`permissionDecisionReason` (verbatim permission
  passthrough); PostToolUse emits `hookSpecificOutput.additionalContext`
  for the distilled summary. The `/index` side-effect path is unchanged
  and verified indexing real search results on the host.
- `apps/plugin/src/hooks/session-start.ts`: unchanged code — the codex
  config passes `--envelope`; misleading comment corrected (Codex shares
  the envelope requirement, Cursor/Antigravity keep bare + .mdc).
- `apps/plugin/package.json`: new `ans-hook-codex` bin →
  `dist/hooks/adapters/codex.cjs`.
- `apps/plugin/test/codex-contract.test.ts` (11 assertions): official
  schema, bin resolution, full-match matcher coverage, `--envelope` on
  SessionStart, generator drift guard (codex config included), envelope
  output shapes, `hook_event_name` precedence + legacy fallback, fail-closed
  ask on unreachable policy, non-ans silent exit, malformed-stdin fail-open.

### D3 Probe discipline (ledger D-002; T1/T2)

Marker = random nonce; judgment = marker reaching the next-turn model
instruction stream, not hook-fired events. Deny sentinels ×4 shapes;
required-MCP sentinel; env-dump hooks for stdin/env truth. `-c` injection
ruled out for hook config (string-typed values); probe injection layers =
CODEX_HOME `config.toml` `[[hooks.*]]` and project `.codex/hooks.json` —
each leg single-layer. Bypass legs explicitly labeled.

## Consequences

- Codex is a fully wired host: shipped config + global bins + envelope-correct
  adapter, verified end to end on 0.142.5.
- `ans-hook-codex` joins the bin surface; hook commands stay PATH-resolvable.
- The `-c` limitation means install/wiring must materialize a config file —
  there is no flag-level hook injection on Codex.
- PostToolUse context injection is opportunistic on Codex (same-turn boundary
  is host-variable); the durable value — project-index accumulation — is
  guaranteed by the `/index` side effect, not stdout.
- `codex-contract.test.ts` + the sentinel/probe scripts are the regression
  net; bare top-level output must not be reintroduced on the codex path.
