# 旧会话没有对话文件，续还是不续

**问题**：旧会话只剩数据库里的消息和记忆、没有完整对话文件时，续聊该怎么办？
评论里给了两条路：A 允许有限恢复，B 要求完整对话文件。这个原型把同一句命令按两条路各走一遍，再看五种出错情况现在会怎样。

来源：[PR #314 的评论](https://github.com/Xxx91n/anysearch-cli/pull/314#issuecomment-6938596532)，对应 #299、#297 S3/S4。

## 怎么跑

双击 `chat-resume-model.html`，浏览器打开就能点。没有服务、没有依赖、不连数据库。

## 页面里有什么

1. **旧会话里有什么**：有数据库消息、记忆摘要、资料和账；没有模型自己的完整对话文件。
2. **同一句命令的两条路**：`ans chat --session 旧会话-甲 "……"`，分别按 A、B 走，看终端输出和留下来的东西。
3. **五种出错情况**：并发收尾、MCP 中途被杀、登记写入失败、改名后读不出、文件后面坏了。每条写清楚用户看到什么、数据留没留、验证到哪一步。
4. **一句话结论**：现在代码是 B；五种情况里哪些有保护、哪些没有。

## 另一份材料

`atomcode-comparison.md`：把 atomcode（`atomgit-atomcode/atomcode`，`ec920b64`）对这几种情况的做法逐条列出来，带源码位置，以及哪些值得借、哪些不值得。

## 结论来自哪里

- 续聊规则、错误文案、列表标签：读 PR #314 的 `chat-session.ts`、`chat.ts`、`session-store.ts`、`pi-session.ts`。
- 没有跑真实库，也没有真的杀进程、改文件名、造损坏文件。页面里每条的“验证”行写明了这一点。

## 不能证明什么

- 不是测试，也不替代安装后的验收。
- 文件损坏、改名加读失败、进程被杀的真实行为没验证。
- A 的输出和文案只是提议，没有实现。
