旧会话没有对话文件，续还是不续？

PR #314 现在选的是“不续”。评论里问你要不要改成“续一半”。这一页把同一件事按两条路各走一遍，再看五种出错情况现在会怎样。

先说清楚：这种旧会话里有什么

有

  • 数据库里的问答记录
  • 记忆摘要：它记得你说过的要点
  • 以前搜过的资料
  • 预算和用量的账

没有

  • 模型自己的完整对话文件
  • 所以完整的问答历史拼不回来

早期版本只把消息写进数据库，没写对话文件。这样的人不算多，但确实有。下面的“旧会话-甲”就是其中一段。

同一句命令，两条路的区别

你在终端里敲这句，明确要用那个旧句柄：

ans chat --session 旧会话-甲 "上次那个报价再算一次"

A 允许有限恢复
B 要求完整文件（现在的代码）

两边都走一遍，区别会写在这里。

五种出错情况，现在会怎样

这些结论是读 PR #314 的代码得出的，不是跑出来的。每条点开看：用户看到什么、数据留没留。

另一个项目（atomcode）怎么做的

  • 旧会话：老格式有内容，就转一次成新日志，旧文件改名留着；只有索引、没有内容文件，就报错，不假装续上。
  • 两轮撞车：一个会话一把锁，只允许一个写者。第二个窗口要续，就从最后提交的状态分一个新会话。
  • 进程被杀：下次打开时补“恢复事实”：已收到的半截回答、结果未知的工具调用、一条提醒，然后把这轮结束掉，不自动重跑。
  • 文件坏了：逐行严格读，坏行报错；只写了一半的尾行不算事实，下次追加时切掉。

完整对照和源码位置写在同目录的 atomcode-comparison.md。那份对照是读源码得出的，没有编译运行 atomcode。

一句话结论

  • 现在的代码选的是 B：找不到完整对话文件就停下，问题不发送，旧数据原样保留。
  • 五种出错里，登记失败和“改名后读不出”已经有明确处理；并发收尾会被后结束的那轮盖掉；文件后面坏了检测不到；MCP 被杀不丢数据，但最近会话不会自动选到它。
  • A 只该开在“用户明确报出旧句柄”这条路上。--continue 还是按完整文件挑，不然它可能自动挑到一段残缺的会话。
